Topophany — 在终端中查看的自托管网络监控

从哪里出发，经由哪条路径，抵达了什么——依据又是什么。

整张网络尽在一屏：哪条路径从哪里走得通，哪些服务有应答，每个状态背后的证据是什么。自托管，一个 Go 二进制文件，在终端里查看。

在线演示 网页版
$ go install github.com/WhitenWhiten/topophany/cmd/topo@latest

03 架构

一个二进制，三种角色

topo 既是客户端，也是采集器和观测点。不需要 CGO、数据库或外部模块。

  • 个二进制文件客户端、采集器和 worker
  • 个外部 Go 模块只有标准库
  • 种发布构建Linux、macOS、Windows · amd64、arm64
  • 个标签页支持鼠标

观测点

采集器

客户端

topo worker家里的笔记本
topo worker东京的服务器
topo serve --observer采集器自身的基准
观测结果，网络分区期间缓冲
topo serve日志 A · 先 fsync 再 ACK
topo serve日志 B · 相互独立
只读快照
topoTUI，支持故障切换
topo --json供脚本使用的快照

两个采集器，不搞共识算法那一套

worker 同时投递给两者，一方离线时先行缓冲。

生来只读

没有远程配置 API，也没有远程 shell。拓扑是你审阅过的本地 JSON。

有上限，也会明说

配额用满时，探测报错停止，而不是丢弃证据。

代理链

  1. 观测点
  2. OpenSSH -W仅限首跳，校验主机密钥

  5. SOCKS5远程 DNS

只读适配器

05 交给 Agent

让 Agent 替你画出这张网

监控最费工夫的一步，是把网络描述清楚，而这恰好是你手边的编程 Agent 擅长的事。它读取机器上现成的信息，写出拓扑，并在任何东西运行之前，先用 topo validate 检查一遍。

这样问它

请把我的网络写成 Topophany 拓扑，保存到 topology.json。格式参考 `topo preview --print-topology` 的输出，以及 github.com/WhitenWhiten/topophany 里的 docs/REFERENCE.md。读取我的 SSH 配置、`tailscale status`，以及你能找到的 Compose 文件和反向代理配置：为每台机器写明所在位置、上面跑的服务、服务所属的应用和监听的地址，再从我要运行 worker 的机器发起检查，并把你了解到的情况写进各台机器的 notes。不要把任何密钥写进文件。反复运行 `topo validate --config topology.json` 直到通过，然后告诉我哪些是查到的、哪些是推测的。

Claude Code、Codex、Gemini CLI、Cursor，或任何能执行命令的 Agent 都行。密钥不会进文件：格式里只写环境变量名和密钥文件的路径，不写内容。

写好之后

  • 网络备忘录topology.json一份审阅过的文件，写清什么跑在哪里、每台机器怎么连上，旁边附着笔记和处置手册。Agent 动手之前先读它；它改了什么，你看 diff 就知道。
  • 随手可查的接口topo status · show · history一条命令，文字或 JSON，你和 Agent 都能用：现在有没有问题、那台服务器上跑着什么、某项检查昨晚表现如何。
  • 上线之前topo preview --config预览模式用合成证据画出你自己的网络，在启动任何一个 worker 之前，你和 Agent 都能先过一遍。

06 在 Mac 上

把网络放进菜单栏

topophany-bar 是 Topophany 的 macOS 伴侣应用。它通过 topo 读取 collector：状态显示在菜单栏，面板告诉你问题是从哪里看到的，桌面小组件让服务器和服务一直留在视野里。

topophany-bar

macOS 26 及以上 · 预发布，从源码构建

GitHub 上的 topophany-bar
  • 一眼看清用图标、数量或几个字显示状态。在内置的抖动夜空「白夜」里，月亮就是状态：一切正常时是满月，有降级时是月偏食，有服务中断时是血月。
  • 从哪里看到事件、受影响的应用和报告问题的观测点集中在一个面板里；任何一项都能在终端界面中打开，查看证据。
  • 直接读取 Beszel 与 Komari从 Beszel Hub 或 Komari 服务器挑选服务器，查看它们的 CPU、内存和磁盘，无需运行 collector。
  • 小组件与主题状态、服务器、服务、地图和时区小组件；六套主题，从原生 macOS 到印在纸上的终端界面。

07 为 iPhone Duo 设计

地图在铰链上方

iPhone App 还没有做。现在有的是 TUI 为它做的设计：--device 让 TUI 按 iPhone、iPad 以及 iPhone Duo 每种姿态的屏幕排版，并在终端里模拟出这块屏幕。在展开的 Duo 上，要看的和要点的分在折痕两侧。

  • 上面看，下面点按笔记本式姿态排版时，地图放在立起的一半，也就是屏幕上；事件和所有控件放在手指所在的平放的一半。
  • 折叠不重绘平放时布局就已经给折痕留出了位置，所以折叠不会移动任何一个字符格。在模拟器里折叠、展开或转向手机，当前的标签页、选中项和打开的证据都会保留。
  • 避开系统区域布局不在折痕上、时钟和摄像头下方、安全区域之外放置控件，每个点按目标都有一指高。测试会检查每台设备上的每个标签页。

在终端里试试

$ go install github.com/WhitenWhiten/topophany/cmd/topo@main $ topo preview --device duo-laptop

[ 和 ] 切换姿态，\ 换下一台设备，鼠标代替手指。终端需要约 99×70 个字符格。下一个版本发布之前，--device 只在 main 上。

在 GitHub 上点 Star 每台设备如何排版

08 安装

一分钟上手

预编译归档，或者一条 go install。

$go install github.com/WhitenWhiten/topophany/cmd/topo@latest

需要 Go 1.26.10 或更新版本。

Linux、macOS、Windows，amd64 与 arm64，附带 SHA256SUMS.txt。

最新发布版
$ git clone https://github.com/WhitenWhiten/topophany $ cd topophany $ go build -trimpath -o topo ./cmd/topo
