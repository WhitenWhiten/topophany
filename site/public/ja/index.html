Topophany — ターミナルで読むセルフホスト型ネットワーク監視

どこから、どの経路で、何に届いたのか — そして、何を根拠に。

ネットワーク全体をひとつの画面に。どの経路がどこから通じているか、どのサービスが応答しているか、それぞれの状態の根拠まで。セルフホストで、Go のバイナリ 1 つ、ターミナルで読めます。

topo はクライアントであり、コレクターであり、観測点です。CGO も、データベースも、外部モジュールも不要。

  • バイナリクライアント、コレクター、ワーカー
  • 外部 Go モジュール標準ライブラリのみ
  • リリースビルドLinux、macOS、Windows · amd64、arm64
  • タブマウス対応

05 エージェントと

地図はエージェントに描かせる

監視でいちばん手間がかかるのはネットワークを書き起こすことで、それは普段使っているコーディングエージェントの得意分野です。マシンが既に持っている情報を読んでトポロジーを書き、何かを動かす前に topo validate で確かめます。

頼み方

私のネットワークを Topophany のトポロジーとして topology.json に書いてください。形式は `topo preview --print-topology` の出力と、github.com/WhitenWhiten/topophany の docs/REFERENCE.md を参考にしてください。SSH の設定、`tailscale status`、見つかる Compose ファイルとリバースプロキシの設定を読み、各マシンについて場所、動いているサービス、サービスが属するアプリケーション、待ち受けているアドレスを宣言し、ワーカーを動かす予定のマシンからのチェックを加え、分かったことはそれぞれのマシンの notes に書いてください。秘密情報はファイルに書かないでください。`topo validate --config topology.json` が通るまで直し、最後に、確かめたことと推測したことを分けて教えてください。

Claude Code、Codex、Gemini CLI、Cursor など、コマンドを実行できるエージェントなら何でも。秘密情報はファイルに入りません。形式に書くのは環境変数名と鍵ファイルのパスだけで、その中身ではありません。

そのあとも

  • ネットワークのメモとしてtopology.json何がどこで動き、各マシンにどう届くのかを、ノートや手順書と一緒にレビュー済みのファイル 1 つに。エージェントは手を動かす前にこれを読み、あなたはその変更を差分で確かめます。
  • すぐ引ける窓口としてtopo status · show · historyコマンド 1 つで、文字でも JSON でも、あなたにもエージェントにも答えます。いま何かおかしいか、あのサーバーで何が動いているか、あのチェックが夜のあいだどうだったか。
  • 動かす前にtopo preview --configプレビューなら、合成の根拠で自分のネットワークを描けます。ワーカーを 1 台も動かす前に、エージェントと一緒に見直せます。

06 Mac で

ネットワークをメニューバーに

topophany-bar は Topophany の macOS 用コンパニオンです。topo を通してコレクターを読み、状態はメニューバーに、問題がどこから見えているかはパネルに、サーバーとサービスはデスクトップのウィジェットに表示します。

topophany-bar

macOS 26 以降 · プレリリース、ソースからビルド

GitHub の topophany-bar
  • ひと目でアイコン、件数、短い言葉で状態を示します。組み込みのディザの夜空「白夜」では月が状態です。すべて正常なら満月、何かが低下すれば部分月食、何かが停止すれば赤い月。
  • どこから見えているかインシデント、影響を受けるアプリケーション、問題を報告しているオブザーバーをひとつのパネルに。どれもターミナル UI で開いて根拠を確かめられます。
  • Beszel と Komari を直接Beszel Hub や Komari サーバーからサーバーを選び、CPU、メモリー、ディスクを見守れます。コレクターは要りません。
  • ウィジェットとテーマステータス、サーバー、サービス、地図、タイムゾーンのウィジェット。テーマは macOS 標準から紙に刷ったターミナル UI まで 6 種類です。

07 iPhone Duo のための設計

地図はヒンジの上に

iPhone アプリはまだありません。あるのは、そのための TUI の設計です。--device は TUI を iPhone、iPad、そして姿勢ごとの iPhone Duo の画面に合わせてレイアウトし、その画面をターミナルの中でシミュレートします。開いた Duo では、見るものと触るものが折り目の両側に分かれます。

  • 見るのは上、触るのは下ノートパソコンの姿勢では、立てた半分（画面）に地図を、指を置く寝かせた半分にイベントとすべての操作を置きます。
  • 折っても描き直さない平らに開いた時点で折り目を空けているので、折ってもセルは 1 つも動きません。シミュレーターの中で折っても、開いても、向きを変えても、タブ、選択、開いた根拠はそのままです。
  • システムの領域を避ける折り目の上、時計やカメラの下、セーフエリアの外には操作を置かず、どのタップ領域も指 1 本分の高さにします。テストがすべてのデバイスのすべてのタブを確かめます。

ターミナルで試す

$ go install github.com/WhitenWhiten/topophany/cmd/topo@main $ topo preview --device duo-laptop

[ と ] で姿勢を切り替え、\ で次のデバイスへ。マウスが指の代わりになります。ターミナルは 99×70 セルほど必要です。次のリリースまで、--device は main にあります。
