# Topophany v1.5.2

Released November 1, 2026.

Topophany 1.5.2 improves setup, investigation and maintenance, adds optional
certificate, latency and JSON response policies, and provides reviewed offline
inventory imports. Verify downloads against `SHA256SUMS.txt`.

## Changes since 1.5.1

- **Guided setup.** Task-based onboarding covers direct resources, a website or
  server, and multi-location networks. `init --url` prepares a real HTTP check
  and matching local credentials for review. Bundled adapter templates,
  enrollment diagnostics and first-evidence progress help complete setup.
- **Coverage and investigation.** Status views distinguish service availability
  from monitoring coverage and explain unknown results. `topo problems` and TUI
  incident sheets group related incidents while preserving independent evidence
  and counter-evidence. Saved views retain perspective, filter and map choices.
  History comparisons pin their collector, time window and measurement contract.
- **Operational diagnostics.** `doctor` covers the collector/viewer pipeline and
  direct sources without exporting private identities. `--json-errors` adds
  structured command failures, and validation reports non-fatal coverage hints.
  Rollout inspection compares collector revisions and worker contracts; local
  runtime records identify loaded private revisions. Isolated recovery checks
  validate a copy without rewriting the original or starting probes.
- **Reviewed configuration changes.** Topology edits detect concurrent changes,
  and batch replacements preview measurement impact before applying. Direct
  profiles can export a collector migration with stable selected-node identities.
  Offline SSH, rendered Compose JSON and Tailscale imports produce bounded,
  private candidates with provenance and paused checks. Imports never run
  commands or probes and never overwrite an existing candidate file.
- **Notification control.** Explicit notification tests and private delivery
  status expose queue, attempt and drop information. Webhooks support timed
  silence, maintenance windows, service routing and a configured primary
  collector. Quiet periods defer notifications while probes and incident
  recording continue. Primary selection is operator policy, with manual
  promotion rather than automatic leader election.
- **Probe policies.** `tls_min_days` warns when a verified peer certificate nears
  expiry. `max_duration_ms` marks successful but slow measured requests as policy
  violations; `policy_threshold` can require sustained evidence. Neither policy
  replaces ordinary request failures. `http.json_equals` adds bounded RFC 6901
  JSON Pointer assertions, distinguishes missing from null, rejects duplicate
  keys and compares number spelling exactly. Expected values remain private.
- **Monitor and browser workflows.** Monitor streams expose standalone checks,
  link evidence and collector-read diagnostics with independent freshness
  deadlines. Compact resource cards can skip history reads, and refreshes retain
  their source. Consumers can detect the additive `investigation` capability.
  Browser viewers remain read-only and offer connection editing, startup recovery
  and localized diagnostics. Critical CLI, TUI and browser workflows are
  localized, with a Chinese task guide.
- **Correctness fixes.** Cloudflare Tunnel checks accept canonical hyphenated
  UUIDs and existing 32-hex IDs. Direct TLS failures remain source-scoped, and
  stale samples do not imply failed source contact. Invalid comparison windows
  fail explicitly, structured configuration errors retain field information,
  and unsupported inventory routes remain inventory-only. Regenerated pages
  reference current WebAssembly hashes and pass site consistency checks.

## Compatibility and upgrades

State schemas remain unchanged from 1.5.1: topology schema 1, batch and snapshot
schema 3, checkpoint schema 2 for external data, monitor protocol 1 and
`direct.schema=1`. Existing configurations remain valid without enabling new
fields. New monitor coverage, source-reason and investigation fields are
additive; consumers must treat an absent capability as unavailable.

Upgrade collectors, workers and viewers before adding `tls_min_days`,
`max_duration_ms` or `http.json_equals`: older binaries reject unsupported
topology fields. Disabled policies preserve existing measurement contracts;
enabling or changing an assertion changes what that check measures. JSON
assertions require a private topology file (`0600` on POSIX), and their expected
values are omitted from public topology projections.

Upgrade collectors before adding notification policy fields. Quiet periods
retain bounded queue age and capacity limits; inspect pending and expired events
before promoting another primary. Fixed-window history comparisons require a
collector that echoes `window_end`; older collectors that ignore the requested
end are rejected rather than silently comparing different periods.

Keep matching topology and notification configuration backups. Rolling back to
1.5.1 requires removing new unsupported fields or restoring those backups; this
release does not require a new state migration. When upgrading from 1.5.0 or
earlier, also follow the collector-first and configuration guidance in the
[1.5.1 release notes](https://github.com/WhitenWhiten/topophany/blob/v1.5.2/docs/releases/v1.5.1.md).

The macOS companion has a separate release lifecycle. This release publishes the
`topo` command-line binaries.

## Acceptance scope

Automated tests use synthetic inventories, temporary directories and loopback
services. They cover policy precedence, JSON bounds and privacy, inventory
review, editing conflicts, notification controls, direct-source isolation,
coverage, diagnostics and monitor contracts. CI and release builds require the
real old-reader compatibility test to execute and pass. Cross-builds verify
compilation for their targets; they do not establish production deployment or
hardware acceptance.

## Downloads

Choose `topophany_1.5.2_<os>_<arch>`: `.tar.gz` for Linux and macOS, `.zip` for
Windows. macOS is `darwin`; Apple silicon is `arm64`, and Intel or AMD 64-bit
systems are `amd64`. Each archive contains `topo` (`topo.exe` on Windows), the
license, the three READMEs and the changelog. `topo version` should report
`Topophany 1.5.2`. Source builds require Go 1.26.10 or newer.
