# Topophany v1.5.3

Released November 1, 2026.

Topophany 1.5.3 adds collector-free checks of this machine's mihomo engine,
shares service assessments and adapter policy evidence with stream consumers,
and corrects adapter judgments, credential reads and Cloudflare token
redaction. Verify downloads against `SHA256SUMS.txt`.

## Changes since 1.5.2

- **This machine's own checks.** `topo local list --json` and
  `topo local inspect|save|remove --json-stdin` manage up to four loopback mihomo
  controllers. Inspect reports version, mode, TUN state and selectable root
  groups without returning their members or selections. Save verifies access
  before writing a private configuration and separate private secret files.
  Revision checks protect concurrent edits.
- **A local stream beside existing sources.** `topo monitor stream` accepts
  `"source":"local"` for `check.card` and `checks.list`, with observer `local`
  ("This machine"). Checks run only while the local stream is open; each new
  request reloads the saved configuration. Unchanged measurement contracts
  retain evidence within that session. There is no collector delivery,
  persistent sample history or background service. `--local-root` selects a
  private store independently of direct profiles and collector credentials.
- **Service assessments in streams.** `service.card` includes the Services
  tab's assessment, separating application availability, path reachability and
  worker state, with scoped evidence and hint codes. The assessment expires at
  its earliest evidence deadline. `service.card` and `services.list` expose
  `unknown_reason`, and summary coverage counts those reasons.
- **Policy and runtime diagnostics.** Stream check diagnostics include measured
  duration, latency and certificate-expiry budgets, and certificate dates.
  Software adapters share the TUI's `not_configured`, `unverified`, `matched`
  and `violated` policy states. Tailscale and WireGuard export bounded runtime
  facts such as online state, transport hints, handshake times, transfer
  counters and keepalive comparisons, without peer names, addresses or keys.
  Private HTTP JSON assertion values remain withheld.
- **A Mihomo starter.** `topo templates mihomo --output mihomo.json` writes a
  fully paused topology. A worker beside the core reads its loopback controller
  using an environment secret and declared mode/TUN policy; a separate HTTP
  check through the core's listener supplies application evidence.
- **Correct evidence judgments.** Resolving a Mihomo chain from provider
  inventory no longer clears missing TUN evidence or a changed provider
  publication. Known policy violations take precedence over unknown results.
  Cloudflare Tunnel connection policies remain unknown when required connection
  or colo evidence is missing. Viewers do not mark incomplete older samples as
  matched policies.
- **Consistent local credentials and TLS.** Local reads take configuration and
  secrets under one lock, including on Windows, so a concurrent save or removal
  cannot mix revisions and credentials. HTTPS `localhost` controllers retain
  their certificate name while dialing the pinned loopback address.
- **Cloudflare response privacy.** API reads stop retaining arbitrary
  `connector_versions` strings, and retained values are scrubbed for embedded
  token fragments. Collectors also remove legacy `connector_versions` facts
  from snapshots and both viewer and monitor history responses. Stored
  journals and existing backups are not rewritten.
- **Acceptance correction.** The process smoke test now passes `show`'s JSON
  flag before its positional argument, matching the CLI parser.

## Compatibility and upgrades

Existing 1.5.2 topologies, collector state and direct profiles need no migration.
Topology schema 1, batch and snapshot schema 3, checkpoint schema 2 for external
data, monitor protocol 1 and `direct.schema=1` remain unchanged. The local
configuration API and store use schema 1 and are separate from direct profiles.

Upgrade the local `topo` binary before configuring local checks. Consumers must
read `topo monitor stream --capabilities` and check for source `local`,
`local.config_api=1` and the metric's source support. A local stream supports
only `check.card` and `checks.list`; it runs as a separate stream beside a
`client` or `direct` stream. Its sample trail covers only the open session;
`latency` and `up_24h` remain `null` because no rollups are kept. The additional
service assessment and diagnostic fields retain protocol 1; consumers must
tolerate absent optional fields when using older binaries.

Upgrade collectors for redaction of legacy Cloudflare facts, workers for new
Cloudflare collection and corrected adapter outcomes, and viewers for the
policy-evidence checks and new stream fields. Collectors can be upgraded before
workers. A new viewer cannot make an older collector's history responses private;
collector redaction requires the collector upgrade. Removing
`connector_versions` changes the available diagnostics without changing the
topology schema or measurement contract. New workers do not recollect that fact.

Local controllers must use `http` or `https` on 127.0.0.0/8, `::1` or `localhost`.
`localhost` dials `127.0.0.1` without DNS resolution and keeps `localhost` for
HTTPS verification. Certificate verification remains enabled. Reads use only
the controller's read-only endpoints; they never change mode, TUN state or a
group selection and never trigger a delay test. A runtime report does not prove
application availability or the route taken by application traffic.

For a local check whose request carries the engine's secret, `reported_chain`
and `reported_selection` keep sanitized engine names and carry
`peer_text: names_kept_local_secret_request`. Those frames stay with the local
user who supplied the secret. Worker checks continue to expose only declared
names, and all other secret-response redactions remain in force.

Rolling back to 1.5.2 requires no collector state conversion, but removes the
new commands, local source, evidence fixes and Cloudflare response protections.
Stop local streams before replacing the binary; older binaries do not use the
separate local store. Keep the collector and worker fixes when those protections
are required. Upgrades from earlier versions must also follow the
[1.5.2 upgrade guidance](https://github.com/WhitenWhiten/topophany/blob/v1.5.3/docs/releases/v1.5.2.md#compatibility-and-upgrades).

The macOS companion has a separate release lifecycle. This release publishes
the `topo` command-line binaries; companion UI support is version-dependent.

## Acceptance scope

Automated tests use temporary private stores, synthetic controller responses
and loopback HTTP/TLS services. They cover local address validation, read-only
inspection, authentication, credential snapshots and concurrent edits, stream
reloads and shutdown, evidence deadlines, policy precedence and response
redaction. CI and release builds require an executed old-reader compatibility
pass. Cross-builds establish compilation for their targets, rather than
production deployment or hardware acceptance.

## Downloads

Choose `topophany_1.5.3_<os>_<arch>`: `.tar.gz` for Linux and macOS, `.zip` for
Windows. macOS is `darwin`; Apple silicon is `arm64`, and Intel or AMD 64-bit
systems are `amd64`. Each archive contains `topo` (`topo.exe` on Windows), the
license, the three READMEs and the changelog. `topo version` should report
`Topophany 1.5.3`. Source builds require Go 1.26.10 or newer.
