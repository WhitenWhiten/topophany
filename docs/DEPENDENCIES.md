# Implementation Dependencies and References

External Go runtime modules: **0**. The native TUI, HTTP API, proxy handshakes, and journal storage are implemented entirely using the Go standard library. Auxiliary local executables are required only when corresponding specialized checks are enabled: OpenSSH `ssh`, Tailscale `tailscale`, and WireGuard `wg`. These binaries are not bundled with this distribution, and simulated environments do not pretend that uninstalled tools are present.

Optional [managed updates](MANAGEMENT.md) use Go's Ed25519, TLS, JSON and archive
implementations, embedded timezone data, GitHub's public API/CDN and a separately
provisioned project publisher root. The Linux helper requires systemd's fixed
`/usr/bin/systemctl`, `/proc` and Unix peer credentials. It queries `dpkg-query`
or `rpm` when present to refuse package-owned executables. It does not depend on
`gh`, a shell installer or Python at runtime. Maintainer publication uses GitHub
CLI attestation verification and pinned GitHub Actions; node-side authenticity
is the project signature plus fresh security catalog, not a partial Sigstore
implementation.

Embedded assets: `internal/tui/land.bin` is a 720x360 1-bit rasterized bitmap (32,400 bytes) derived from [Natural Earth](https://www.naturalearthdata.com/) 1:110m physical land polygons (public domain). It is generated by `scripts/gen_landmask.py` (standard-library Python 3) from `ne_110m_land.geojson`, and is used by the dot-matrix geographic topology map and the rotating globe in the About view. The built-in city coordinates table contains approximate reference coordinates used solely for form autocompletion.

Scripts `verify.py`, `smoke.py`, and `gen_landmask.py` are intended solely for development verification, smoke testing, and asset generation, requiring Python 3. Running the compiled `topo` binary requires no Python runtime.

Local verification does not publish through GitHub Actions. Because external
CLIs/APIs can evolve, unexpected responses must fail explicitly rather than
silently weakening verification. Workflows pin actions to immutable commit SHAs.
Tests/builds retain read-only repository access; provenance construction also
needs `id-token: write` and `attestations: write`. Only isolated publication jobs
receive `contents: write`, without executing downloaded release code.
Repository/environment protection and publisher custody require maintainer setup.
